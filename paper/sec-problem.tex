\section{Typed Plans and Verified Query Planning}
\label{sec-problem}

This section formalizes query plans as typed terms of the SPARQL
algebra and states the planning problem that \hermes solves.

\subsection{Plans}

\begin{definition}[Plan]
A plan $\pi$ consists of
a set $T$ of triple patterns;
a set $F$ of filter expressions;
optional groups $O$, union branches $U$, and minus groups $M$, each a
set of triple patterns;
extensions $X$, pairs $(e, ?v)$ of an expression and a variable;
group-by variables $\Gamma_{\!g}$;
aggregates $A$, pairs $(\alpha, ?v)$;
group filters $H$;
order keys $R$;
projected variables $\Pi$;
a distinct flag $\delta$;
a slice $\ell$;
and a query form $f \in \{\kw{SELECT}, \kw{ASK}\}$.
\end{definition}

A plan denotes the SPARQL query obtained by joining $T$, applying the
optional, union, minus, extension, and filter operators in that order,
then grouping, aggregating, filtering groups, ordering, projecting, and
slicing.
Rendering is deterministic, so a plan and its query are interchangeable.
An \emph{action} is a total function from plans to plans that applies
one operator of Table~\ref{tab-ops}; the action \kw{remove} retracts a
triple pattern or a filter.
Plans are immutable, so a sequence of actions is a path
$\pi_0 \to \pi_1 \to \cdots \to \pi_k$ from the empty plan $\pi_0$.

\subsection{Typing}

Let $\vars(t)$ be the variables of a pattern or expression $t$.
A \emph{typing context} $\Gamma$ maps each variable to a set of types.
For a plan $\pi$ over schema $\Sc$, $\Gamma_\pi$ is the least context
closed under the rules below, applied to every triple pattern in $T$,
$O$, $U$, and $M$:
\begin{gather*}
\frac{(?x,\ \kw{rdf{:}type},\ c) \quad c \in C}{c \in \Gamma(?x)}\ (\textsc{T-Type})
\\[1ex]
\frac{(?x,\ p,\ o) \quad d \in \dom(p)}{d \in \Gamma(?x)}\ (\textsc{T-Dom})
\\[1ex]
\frac{(s,\ p,\ ?y) \quad r \in \rng(p)}{r \in \Gamma(?y)}\ (\textsc{T-Rng})
\end{gather*}
Types are compared up to $\sub$.

\begin{definition}[Well-typed plan]
A plan $\pi$ is \emph{ill typed} if
(1) a literal occurs in subject position;
(2) a literal is the object of a property $p$ whose range contains a
class;
(3) some variable has both a datatype and a class in $\Gamma_\pi$; or
(4) a class or property in a namespace that $\Sc$ describes is not in
$C$ or $P$.
Otherwise it is \emph{well typed}.
Two classes in $\Gamma_\pi(?x)$ that are incomparable under $\sub$ are
reported as a warning, not an error, because RDF makes the open-world
assumption and the schema need not declare disjointness.
\end{definition}

\begin{definition}[Well-formed plan]
Let $S_\pi$ be the variables bound by the patterns of $\pi$ and by its
extensions, and let $S^+_\pi = S_\pi \cup \{?v \mid (\alpha, ?v) \in A\}$.
A plan is \emph{well formed} if
$\vars(e) \subseteq S_\pi$ for every filter and extension expression;
no extension binds a variable already in $S_\pi$;
$\Gamma_{\!g} \subseteq S_\pi$;
the variables of $H$, $R$, and $\Pi$ are in $S^+_\pi$; and,
when $A$ or $\Gamma_{\!g}$ is non-empty, every variable of $\Pi$ that
is in $S_\pi$ is also in $\Gamma_{\!g}$.
\end{definition}

A plan that is both well typed and well formed is \emph{valid}, written
$\Sc \entails \pi$.
Validity is decided from $\pi$ and $\Sc$ alone, without evaluating
$\pi$ on $\G$.

\subsection{Goals}

A question constrains the shape of its answer before any query exists:
``which department'' asks for entities of one class, ``how many'' for a
number, ``is there'' for a Boolean.

\begin{definition}[Goal]
A goal is $\sigma = (\vec{a}, \kappa, c, m)$: answer variables
$\vec{a}$, a kind
$\kappa \in \{\kw{entity}, \kw{literal}, \kw{number}, \kw{boolean}\}$,
an optional type $c$, and a cardinality $m \in \{\kw{one}, \kw{many}\}$.
A valid plan $\pi$ \emph{satisfies} $\sigma$, written
$\pi \models \sigma$, if:
for $\kappa = \kw{boolean}$, $f = \kw{ASK}$;
otherwise $f = \kw{SELECT}$, every $a \in \vec{a}$ is in $S^+_\pi$ and
projected, no other variable is projected, a numeric kind is witnessed
by an aggregate or a numeric datatype in $\Gamma_\pi(a)$, an entity
kind has no datatype in $\Gamma_\pi(a)$, and, if $c$ is given, some
type in $\Gamma_\pi(a)$ is subsumed by $c$.
The cardinality $m = \kw{one}$ is checked after execution:
$|\eval{\pi}{\G}| = 1$.
\end{definition}

The goal is derived from the question by the planner, so it can be
wrong; satisfaction guarantees that the plan has the shape the goal
asks for, not that the goal reflects the question.

\subsection{The Planning Problem}

\begin{definition}[Verified query planning]
Given a question $q$, a graph $\G$, and its schema $\Sc$, a planner
states a goal $\sigma$ and produces actions $a_1, \dots, a_k$, leading
to plans $\pi_1, \dots, \pi_k$.
After each action it receives an observation
$o_i = (\mathit{ok}_i, n_i, n_{i-1}, \mathit{rows}_i, \mathit{err}_i)$:
whether $\pi_i$ is valid and runs, its number of solutions
$n_i = |\eval{\pi_i}{\G}|$, the previous count, a sample of rows, and
an error message.
An action whose plan is not valid is rejected and not executed.
The output $\pi_k$ must satisfy $\Sc \entails \pi_k$ and
$\pi_k \models \sigma$; among such outputs, the objective is the set
$F_1$ of $\eval{\pi_k}{\G}$ against the intended answers of $q$.
\end{definition}

The intended answers are unknown at planning time, so the objective
cannot be optimized directly; the observations are the evidence the
planner has.
Three properties make the action space suitable for planning.

\begin{proposition}[Monotone refinement]
\label{prop-monotone}
Let $\pi$ be a plan without optional, minus, union, aggregation, or
slice, and let $\pi'$ apply \kw{triple} or \kw{filter} to $\pi$.
Then every mapping in $\eval{\pi'}{\G}$, restricted to $S_\pi$, is a
mapping in $\eval{\pi}{\G}$.
\end{proposition}

\begin{proof}[Proof sketch]
A mapping of $\pi \bowtie t$ is the union of a compatible mapping of
$\pi$ and one of $t$, so its restriction to $S_\pi$ is a mapping of
$\pi$.
Filtering only removes mappings.
\end{proof}

Proposition~\ref{prop-monotone} is what makes the count in an
observation informative: within the conjunctive fragment, adding a
constraint can only narrow the answers seen through the variables
already present, so a drop from 53 solutions to 1
(Example~\ref{exa-motivation}) is evidence that the constraint is
selective.

\begin{proposition}[Static soundness]
\label{prop-sound}
If the verifier of Section~\ref{sec-framework} accepts $\pi$, then
$\Sc \entails \pi$.
\end{proposition}

\begin{proposition}[Checking cost]
\label{prop-cost}
After a one-time closure of $\sub$, deciding $\Sc \entails \pi$ and
$\pi \models \sigma$ takes time linear in the size of $\pi$, up to the
cost of set lookups in $\Sc$.
\end{proposition}

Proofs of Propositions~\ref{prop-sound} and~\ref{prop-cost} are in
Appendix~A.

\stitle{RDF graphs and ontologies}.
Let $I$ and $L$ be disjoint sets of IRIs and literals; blank nodes are
treated as IRIs.
An RDF graph $\G$ is a finite set of triples
$(s, p, o) \in I \times I \times (I \cup L)$.
An ontology $O = (C, E)$ over $\G$, its schema, has classes $C \subseteq I$ and
properties $E \subseteq I$, a domain $\dom(p) \subseteq C$ and a range
$\rng(p) \subseteq C \cup D$ for each property $p \in E$, where $D$ is a
set of datatypes, and the reflexive--transitive closure $\sub$ of
\kw{rdfs{:}subClassOf}~\cite{rdfs11}.
A \emph{type} is a class or a datatype; $\Lit$ denotes the datatypes
and \kw{rdfs{:}Literal}.

\stitle{The SPARQL algebra}.
Let $V$ be a set of variables, disjoint from $I \cup L$.
A triple pattern is a triple over $I \cup L \cup V$.
Following Pérez et al.~\cite{perez2009semantics} and the SPARQL 1.1
specification~\cite{sparql11}, a solution mapping $\mu$ is a partial
function from $V$ to $I \cup L$, two mappings are compatible when they
agree on their shared variables, and a graph pattern $P$ evaluates on
$\G$ to a multiset of mappings $\eval{P}{\G}$.
Patterns are built from basic graph patterns (BGPs) by the operators in
Table~\ref{tab-ops}.
Evaluating SPARQL graph patterns is PSPACE-complete in
general~\cite{perez2009semantics}, so running a plan to inspect it is
not free, which motivates checking what can be checked without
running it.

\stitle{Natural language to SPARQL}.
Given a question $q$, a graph $\G$, and its ontology $O$, the task is to
produce a query whose answers on $\G$ match the intended answers of
$q$.
Following the Text2SPARQL evaluation~\cite{text2sparql}, answers are
compared as sets of values: every value bound to every projected
variable counts once, and quality is measured by set precision, recall,
and $F_1$ against the answers of a gold query.

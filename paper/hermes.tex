\title{Hermes: Verified Query Planning over the SPARQL Algebra with Language Agents}

\author{Lam Nguyen}
\affiliation{%

  \city{Cleveland}

\email{ltn18@case.edu}

\begin{abstract}
Translating natural-language questions into SPARQL lets users query
knowledge graphs without learning their schema, and is a basic step in
question answering over knowledge graphs.
Large language models (LLMs) now write plausible SPARQL, but they write
the whole query at once.
A query that fails to parse, joins values of incompatible types, or
returns nothing is detected only after it is complete, and the repair
is another guess.
This paper introduces \hermes, a query-planning agent that builds a
SPARQL query one operator of the SPARQL algebra at a time, over a typed
formalization of the language.
(1) We formalize SPARQL query plans as terms of a typed algebra: an RDF
schema induces a type for every query variable, and well-formedness and
typing rules decide, without evaluating the query, whether a plan is
valid.
(2) We formulate natural language to SPARQL as verified query planning.
Actions are algebra operators; after each one, the agent observes its
effect on the graph (the number of solutions, how it changed, a sample
of rows, and any error); and a plan is accepted only when it is well
typed and satisfies a goal derived from the question.
(3) We implement a verifier that rejects ill-typed steps before they
reach the graph store, and an LLM planner that drives it.
(4) We normalize six benchmarks into one format and implement a scorer
that reproduces every published Text2SPARQL 2026 score.
We evaluate with Qwen3 models of 4B, 8B, and 14B parameters.
On the Text2SPARQL 2026 corporate benchmark with the 14B model,
\hermes reaches a set $F_1$ of 0.282, against 0.231 without the
verifier, 0.197 for constraint-guided search, and 0.089 for one-shot
generation, at a higher model-call budget; the verifier cuts the items
without a runnable query from 26 to 9.
\end{abstract}
